# Первый бейзлайн

## Запуск

Сравнил шесть методов прунинга на уровнях 30, 50, 70 и 90%. Получилось 24 варианта, каждый начинался с `base.pth`. Обучение проходило на MacBook M4 через MPS, зерно 0.

Сначала измерял качество сразу после прунинга, затем дообучал модель 20 эпох: AdamW, learning rate `2e-4`, batch 16, cosine decay. Лучшую эпоху выбирал по Dice val. Отдельного восстановления статистик BN в этом запуске не было.

| Метод | Как выбирались каналы или веса для удаления |
|---|---|
| `random` | В каждой группе случайно выбирал каналы для удаления |
| `l1` | В каждой группе удалял каналы с наименьшей L1-нормой весов, то есть суммой модулей весов |
| `fpgm` | Для фильтров считал сумму расстояний до остальных фильтров по их весам. Удалял фильтры с наименьшей суммой |
| `bn_scale` | Брал множитель каждого канала в BatchNorm и удалял каналы с наименьшим модулем этого множителя |
| `taylor` | Собирал градиенты на 16 батчах train. По каналам суммировал модули произведений весов на градиенты и удалял каналы с наименьшей суммой |
| `unstructured_l1` | Веса с наименьшим модулем заменял нулями |

У пяти структурных методов в каждой группе удалялась заданная доля каналов. Связанные каналы удалялись вместе через Torch-Pruning.

Неструктурный L1 заменял часть весов нулями. Количество хранимых весов, число каналов и размеры слоев оставались прежними.

Скорость измерял при batch 1: 20 прогревов, затем 100 измерений, результатом брал медиану. Проверил PyTorch на CPU в один и все потоки, MPS и ONNX Runtime на CPU в один и все потоки.

```bash
.venv/bin/python src/prune_baseline.py
.venv/bin/python src/benchmark.py
.venv/bin/python src/report.py
```

## Результаты

Dice test после дообучения, одно зерно. У исходной модели: 0,9244.

| Метод | 30% | 50% | 70% | 90% |
|---|---:|---:|---:|---:|
| random | 0,9214 | 0,9096 | 0,9044 | 0,8667 |
| l1 | 0,9164 | 0,9212 | 0,9066 | 0,8348 |
| fpgm | 0,9247 | 0,9133 | 0,9024 | 0,0000 |
| bn_scale | 0,9212 | 0,9108 | 0,8810 | 0,0000 |
| taylor | 0,9211 | 0,9165 | 0,9008 | 0,0000 |
| unstructured_l1 | 0,9205 | 0,9198 | 0,9244 | 0,9233 |

На 50% структурный прунинг уменьшил число параметров с 24,44 до 6,12 млн, а время CPU в один поток с 45,9 до примерно 21,8 мс. L1 сохранил Dice 0,9212. На 70% осталось 2,17 млн параметров, время сократилось примерно до 12,6 мс, качество снизилось у всех структурных методов.

На 90% random дал Dice 0,8667, L1: 0,8348. FPGM, BN scale и Taylor после дообучения остались с Dice около нуля.

Неструктурный L1 сохранил высокое качество даже на 90%. Файл не уменьшился, как и ожидалось: 93,4 МБ. Время практически не изменилось.

Полная таблица с IoU, PH2, размерами и временем: [summary.md](../runs/results/summary.md). Исходные данные: [prune_results.csv](../runs/results/prune_results.csv), [benchmark.csv](../runs/results/benchmark.csv).

## Наблюдения и решения для своего метода

| Наблюдение | Решение |
|---|---|
| Неструктурный прунинг сохранял качество, но не уменьшал файл и время | Физически удалять каналы. Неструктурный L1 использовать как подсказку, каким группам оставить больше каналов |
| Random оказался сопоставим с остальными критериями | Искать распределение числа каналов по группам. Внутри групп оставить выбор по L1-норме, random сохранить в сравнении |
| Сразу после удаления каналов Dice часто падал к нулю | В полном прогоне перед отдельным замером восстанавливать статистики BN на train без изменения весов, затем повторно измерять Dice |
| На 90% три метода не восстановили качество; в последнем блоке декодера оставался один канал | Проверить неравномерное распределение, минимальную ширину групп и постепенное гашение каналов перед удалением |
| GMACs сокращались сильнее, чем время | Сохранить отдельные замеры скорости на CPU и ONNX Runtime |
| Один запуск не показывал разброс | В полном эксперименте использовать три зерна и отдельно проверить вклад каждого компонента метода |
